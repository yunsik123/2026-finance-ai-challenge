# 프론트 기능 점검 및 회귀 검증

디자인, CSS, 이미지 자산은 변경하지 않고 로그인·투자·쿠폰·문의·심사·AI 화면의 데이터 흐름을 점검했습니다.

## 수정한 문제

- 초기 API 실패 시 무한 로딩에 머무르던 문제: 오류 안내와 재시도를 제공하고, 갱신 실패 시 기존 화면을 유지합니다.
- `/api/me`의 일시적 장애까지 로그아웃으로 처리하던 문제: 인증 만료(401)와 통신·서버 오류를 구분합니다.
- 로그아웃·계정 전환 중 늦게 도착한 응답이 이전 계정 데이터를 복원하던 문제: 요청 순서와 요청 당시 토큰을 확인하고 계정별 화면 상태를 초기화합니다. 다른 탭의 로그인 변경도 반영합니다.
- 동일 역할의 다른 계정에 AI 대화·문의 내역이 남던 문제: 계정 전환 시 관련 컴포넌트를 초기화하고 진행 중인 AI 요청을 취소합니다.
- 점주 화면이 신청 개수 변경 때만 갱신되던 문제: 최신 원장 갱신에 맞춰 쿠폰·모금·공개 설정을 다시 읽습니다.
- 식당·심사·예약 거래·교환 내역의 응답 역전: 최신 요청만 상태에 적용합니다.
- 문의 접수 후 비동기 이벤트의 `currentTarget`을 읽다가 오류가 발생하던 문제: 제출 시 폼 요소를 보관합니다.
- 파일 교체·비우기 후 이전 메타데이터나 OCR 결과가 적용되던 문제: 현재 선택된 파일과 일치하는 결과만 적용합니다. 신청 자료 읽기 단계부터 중복 제출과 입력 변경을 막습니다.
- 문서 미리보기의 Object URL 생성·해제 수명 불일치: effect 안에서 URL을 생성하고 해당 effect의 정리 단계에서 해제합니다.
- AI 비교 선택·매출 이력 변경 후 오래된 분석 표시: 관련 수치 변경 시 다시 분석하고 선택 해제 시 결과를 비웁니다.
- 약관 요청 실패 후 복구되지 않거나 다른 문서의 본문이 남던 문제: 재시도·초기화와 버전 갱신을 적용합니다. 버전이 바뀌면 거래·심사 동의를 다시 받습니다.
- 매출 이력이 줄었을 때 차트의 선택 인덱스가 범위를 벗어나던 문제 및 찜 버튼의 키보드 이벤트가 식당 카드로 전파되던 문제를 수정합니다.

## 실행

```sh
npm run build
npm run test:amount
npm run test:client
MEOKTU_TEST_PORT=8891 npm run test:integration
npm run test:browser
```

`test:browser`는 시스템 Chrome을 사용합니다. macOS 기본 경로가 아닌 환경에서는 `CHROME_PATH`에 실행 파일 경로를 지정합니다. `MEOKTU_BROWSER_PORT` 기본값은 8892입니다.

브라우저 검증은 임시 데이터 디렉터리, 새 Chrome 프로필, 파일 DB로 별도 서버를 실행합니다. 종료 시 자체 서버·브라우저·임시 데이터를 정리합니다. 통합 테스트도 `STATE_STORE=file`, `AI_DISABLED=1`, `NEO4J_URI=''`, `SUPABASE_AUTH_DISABLED=1`을 강제해 운영 원장과 외부 AI를 사용하지 않습니다. 이미 사용 중인 포트의 개발 원장을 자동으로 재사용하지 않습니다.

## 검증 범위

- 통합 테스트 12개 묶음: 투자·회수·예약 체결, 쿠폰 에스크로·취소·중복 처리, 권한·개인정보 경계, 체험 세션 분리, 점주 심사·관리자 승인, AI 원장 답변·규칙 대체 응답, 정적 페이지·딥링크.
- API 클라이언트: Headers 병합, 인증 오류 상태, HTML 오류 응답, 잘못된 성공 응답, 204, FormData.
- 실제 Chrome: 초기 요청 실패·재시도, 일시적 계정 API 장애, 충전·약관 동의 투자와 잔액 검증, 문의 접수·폼 초기화, AI 대화와 로그아웃 응답 역전, 다른 탭 세션 변경·만료, 공개 경로, AI 비교 선택, 점주 리포트·샘플 11종·이미지 미리보기·펀딩 신청, 관리자 탭·심사 상세, 미처리 JavaScript 오류.
- 운영 읽기 확인: `/api/health`에서 PostgreSQL·Neo4j·Vertex 설정을 확인했고, 공개 식당 비교 요청에서 `provider=google-vertex-ai`, `cached=false` 응답을 확인했습니다. 운영 거래 원장을 수정하는 테스트는 수행하지 않았습니다.

배포 워크플로는 타입 검사·API 클라이언트 검사·빌드·통합 테스트를 통과해야 배포합니다. 실제 브라우저 검사는 위 명령으로 별도 실행합니다.
