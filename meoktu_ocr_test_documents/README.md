# 먹투 실제 양식 대응 참고팩

이 묶음은 실제 기관 서식과 공개된 실물·업체 화면을 바탕으로 만든 OCR 참고자료입니다.

## 폴더 구성

- `actual_public_examples`: 실제 발급본을 공개자가 마스킹한 이미지. 필드 위치·사진 품질·문서 분류 테스트에 적합합니다.
- `official_forms_pdf`: 국가법령정보센터의 공식 빈 서식 PDF와 페이지별 PNG. 표·라벨·레이아웃 인식 테스트에 적합합니다.
- `variable_vendor_screens`: POS·은행·카드·배달 정산의 공개 화면 예시. 업체별 형식 차이를 확인하는 참고자료이며 공통 표준양식은 아닙니다.

## 중요한 제한

1. 공개 실물 예시는 개인정보가 가려져 있으므로 실제 값 추출 정답률 평가에는 부적합합니다.
2. `식품 영업 신고서`는 영업신고증 발급을 위한 공식 신청서입니다. 실제 발급 `영업신고증` 레이아웃은 공개 실물 예시를 참고하세요.
3. POS·은행·카드·배달 자료에는 전국 공통 양식이 없습니다. 실제 서비스는 CSV/XLSX/PDF 원본 업로드와 업체별 파서를 병행하는 편이 좋습니다.
4. 제3자 공개 이미지는 내부 개발·검증용으로만 사용하고 서비스 화면의 샘플로 재배포하지 않는 것을 권장합니다.

## 이 참고팩을 코드에 어떻게 반영했는가

이 묶음은 참고자료로만 두지 않고 아래 네 곳에 실제로 반영했습니다.

1. **영업신고번호 입력 규칙** (`src/OwnerCenter.tsx`) — 공개 실물 예시의 신고번호가
   `제 2024-0123 호`처럼 연도·관할구청·일련번호가 섞인 형태로 발급된다는 것을 확인해,
   숫자만 받던 검사를 '서식 글자(제·호)를 떼고 숫자·하이픈·관할구청명만 허용하되
   4자리 이상 숫자가 반드시 있을 것'으로 바꿨습니다. 숫자만 받으면 실제 사장님이
   신고증에 적힌 번호를 그대로 넣을 수 없습니다.
2. **판독 프롬프트의 라벨 변형** (`server/index.ts`) — 실제 사업자등록증은
   사업자등록번호를 `등록번호`, 대표자를 `성명`, 개업일을 `개업연월일`,
   업종을 `업태/종목`으로 적습니다. 영업신고증은 상호를 `영업소 명칭`,
   업종을 `영업의 종류`로 적습니다. 이 라벨들을 판독 지시문에 명시했습니다.
3. **신고서(신청서) 오제출 차단** (`server/documents.ts`) — `식품 영업 신고서`는
   영업신고증을 받기 위해 내는 신청서지 발급본이 아닙니다(위 제한 2번).
   `별지 제○호서식`·`영업신고서` 같은 표기를 만나면 영업신고증으로 분류하지 않고
   "발급받은 영업신고증이 필요하다"고 되돌려줍니다.
4. **표 자료 열 이름 신호** (`server/documents.ts`) — 은행 거래내역 저장 화면의 실제
   열 이름(`거래일자·적요·출금(원)·입금(원)·내용·잔액(원)·거래점`)을 계좌 자료
   분류 신호에 넣었습니다. POS·카드·배달은 전국 공통 양식이 없다는 제한 3번을
   근거로, 양식이 아니라 열 이름으로 분류하는 현재 방식을 유지합니다.

## 서비스 데모 자료는 별도입니다

`public/samples` 의 01~10번 문서는 이 폴더의 제3자 이미지가 아니라
`scripts/sample-docs/synthetic.mjs` 가 만드는 자체 합성 문서입니다(제한 4번).
`node scripts/make-sample-docs.mjs` 로 다시 만들 수 있고, 사업체 정보는
그 파일의 `PROFILE` 한 곳에만 있습니다.
